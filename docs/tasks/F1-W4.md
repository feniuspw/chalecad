# F1-W4: SQLite persistence, project list, named versions, and PDF

**Goal:** save projects on the local server (Drizzle + SQLite, `DATA_MODE=sqlite`), a projects page, named versions, and PDF export with floor plans and the materials list.

**May change:** `apps/web/lib/db/**`, `apps/web/lib/storage/http.ts`, `apps/web/lib/storage/index.ts`, `apps/web/app/api/**`, `apps/web/app/projetos/**`, `apps/web/lib/pdf/**`, `apps/web/components/pdf/**`, `apps/web/components/projects/**`, `apps/web/components/editor/VersionsDialog.tsx` (new), `apps/web/scripts/**`, `apps/web/drizzle.config.ts`, `apps/web/lib/plan2d/**` (+ tests).
**Do not change:** contracts in `lib/store/types.ts` and `lib/storage/types.ts`, `components/scene/**`, `components/results/**`, `packages/**`, `package.json`. To wire new buttons into the editor (Versions, PDF, link to Projects), describe in the return exactly where and how; the orchestrator fits them in. Exception: you may edit `apps/web/components/editor/TopBar.tsx` (or the equivalent top bar file) only to add these 3 buttons.

## Deliverables
1. **Database** `lib/db/`: Drizzle schema (`projects`: id, name, typology, data JSON, builtArea, total, thumbnail, createdAt, updatedAt; `versions`: id, projectId, name, data JSON, createdAt) for SQLite (better-sqlite3, file `./data/chalecad.sqlite` relative to the app root, created if it does not exist). `scripts/migrate.mjs` creates the tables (idempotent DDL; `pnpm db:migrate`). Automatic migration on first connection as well. `getDb()` abstraction that reads `DATA_MODE` (`sqlite` default; `supabase` throws a clear error "não configurado neste ambiente" (not configured in this environment)).
2. **API** (route handlers, `runtime = 'nodejs'`): `GET/POST /api/projects`, `GET/PUT/DELETE /api/projects/[id]`, `GET/POST /api/projects/[id]/versions`, `GET/DELETE /api/versions/[id]`. Body validation with the engine's `Project` schema (Zod). JSON errors with a pt-BR message.
3. **HttpAdapter** `lib/storage/http.ts` implementing `StorageAdapter`. `lib/storage/index.ts`: `getStorage()` uses HttpAdapter when the API responds (check `/api/health`, create that route) and falls back to IndexedDB when offline; keep the `getLocalStorage()` function (IndexedDB) for fast autosave.
4. **`/projetos` page**: grid of nice cards (name, typology with icon, area, total cost, updated X ago, thumbnail if any), search, sort, "Novo projeto" (New project; goes to `/editor?new=1`), duplicate, rename, delete with confirmation, import JSON. Inviting empty state.
5. **Named versions** `components/editor/VersionsDialog.tsx`: save a version with a name, list, restore (loads into the editor with `loadProject`, after confirmation), quick compare (shows area/cost/weight difference if `results` are available via `EngineWorkerApi.computeMany`, optional), delete.
6. **2D floor plans** `lib/plan2d/`: pure functions that generate SVG (string) from the `BuildingModel`: plan per level (walls with thickness and hatching, openings with a door swing arc and a triple-line window, stair with arrows, dashed mezzanine on the ground floor, exterior and main interior dimensions, north arrow, and graphic scale), front and side elevations (wall outlines, roof, openings). Tests: valid SVG and contains the expected elements.
7. **PDF** `lib/pdf/` + `components/pdf/` with `@react-pdf/renderer` (generated on the client, download): cover (name, date, typology, area, total, ART (Anotação de Responsabilidade Técnica, the engineer's liability record) notice highlighted), plans and elevations (SVG → react-pdf `<Svg>` or PNG image via canvas), area table, materials list per stage (table), budget per stage with totals and range, warnings, assumptions (profiles, spacing, assemblies, price base and date). **ART notice in the footer of every page.** Page numbering. Clean typography (react-pdf's embedded Helvetica).
8. Function `exportPdf(project, results)` exported from `lib/pdf/index.ts` for the editor to call.
