# F14-W2: Presentation — async preparation with progress, sloped terrain, and trees

User feedback:
1. Clicking **"Apresentação"** (Presentation) freezes the screen for seconds (1024 px procedural textures, foliage, and terrain generated synchronously) with no notice, and they cannot tell whether it hung. They want:
   - a notice "Preparando a apresentação…" (Preparing the presentation…) with a **progress bar** and **"Cancelar"** (Cancel), while they keep using the editor;
   - when it finishes, a notice "Apresentação pronta" (Presentation ready) with an **"Abrir"** (Open) button that enters directly and instantly;
   - if the project did not change, entering again is immediate (uses what was already prepared); if it changed, it prepares again with the same flow.
2. In a project with sloped terrain (`site.type === 'sloped'`, 10%), the Presentation **did not show the slope** (only a light platform on a plane) and had **no trees**:
   - in `components/scene/PresentationLights.tsx`, with `hasTerrain` the `Landscape` (trees, hills, path) is replaced by a `GrassGround` 8 m below;
   - `TerrainView` draws only the lot.

**May change:** `apps/web/components/scene/**`, `apps/web/lib/three/**`, `apps/web/components/editor/**` (only what connects the view-mode button to the new flow), `apps/web/lib/store/editor.ts` (only if indispensable; prefer the `presentationUi` store), plus the tests alongside.

**Do not change:** `packages/**`, `lib/project/**`, `components/wizard/**` (F14-W1 in parallel).

## 1. Async preparation
- New module `lib/three/presentationPrep.ts` with `preparePresentation(signal, onProgress)`:
  - runs in steps, yielding to the browser between them (`await` of `requestIdleCallback`/`setTimeout(0)`/`scheduler.yield` if available);
  - steps:
    1. PBR textures of each material used in the project, at the presentation quality (`getPbrMaps` in `pbrTextures.ts`; one material per step);
    2. photos (`photoTextures.ts`, wait for loading);
    3. foliage and landscape data (`foliage.ts`, `landscape.ts`, which are pure and can be precomputed and memoized);
    4. the terrain;
  - progress from 0 to 1 by step weight;
  - cancelable by `AbortSignal`.
- Memoize the result by a project signature (hash of a stable JSON of the project plus the quality and the scenery). Entering with the same signature is instant.
- Retain the prepared textures (`retainPbr`) until leaving the presentation or until the signature changes, so the 4 s sweep does not discard them.
- **Interface:**
  - clicking "Apresentação" without a ready preparation **does not switch the mode**: it starts the preparation and shows a fixed notice (sonner with `toast.custom`, or a floating card in the viewport corner) with "Preparando a apresentação… 42%", the bar, and "Cancelar". The editor remains usable;
  - when finished: "Apresentação pronta", with the **"Abrir"** button, which switches the mode. If the user clicks "Apresentação" again, it opens directly;
  - if the project changes during preparation, it restarts by itself; if it changes afterward, the next click prepares again;
  - if the browser does not support `requestIdleCallback`, use `setTimeout`.
- The scene components (`usePbrProps`, `Landscape`, `Vegetation`, `TerrainView`) use the memoized data when it exists, so mounting is light.
- On entering, if there is still heavy work in mounting, show an overlay "Montando a cena…" (Assembling the scene…) over the canvas until the first frame with everything ready (never a stalled screen without notice).
- The current shortcuts and flow ("Andar por dentro" (Walk inside), photos, video) keep working. The existing e2e tests that click "Apresentação" must keep passing: adjust them in `apps/web/e2e/` to click "Abrir" when the notice appears, or expose a path that opens directly when the preparation is already ready.

## 2. Sloped terrain in the presentation
- With sloped terrain, **also** draw the `Landscape` (trees, shrubs, hills, path):
  - the lot terrain (`TerrainView`) shows the real slope, with the pad, cut, and fill;
  - around it, the landscape mesh continues the lot's slope (same slope plane, the site's `slopePct` and `downhillAzimuthDeg`) until it blends with the hills;
  - vegetation and the path are positioned at the terrain height (sample the height function), never floating or buried;
  - do not put trees on the pad, the house, the cut, or the fill.
- Grass in the sloped terrain's texture (the same procedural `grass` tinted by the scenery), not the flat light color of today.
- Pure tests: the combined height function is continuous at the lot edge, trees sit within ±0.05 m of the surface, and no tree is inside the pad rectangle + 1 m.
