# F1-W1: Editor — state, Web Worker, autosave, wizard, and properties panel

**Goal:** connect the editor to the engine: global state with undo/redo, computation in the Web Worker, local autosave, new-project wizard, and parametric properties panel. At the end, changing any parameter updates the 3D view instantly.

**May change:** `apps/web/lib/store/editor.ts` (+ tests), `apps/web/lib/engine/**`, `apps/web/workers/**`, `apps/web/lib/storage/indexeddb.ts`, `apps/web/lib/storage/index.ts`, `apps/web/lib/project/**`, `apps/web/components/editor/**`, `apps/web/app/editor/**`, `apps/web/hooks/**`.
**Do not change:** `apps/web/lib/store/types.ts` and `apps/web/lib/storage/types.ts` (orchestrator contracts), `apps/web/components/scene/**` (only use the components; if you need a new prop, stop and explain), `apps/web/components/results/**`, `packages/**`, `package.json`.

The engine (`@chalecad/engine`) currently exports `loadProject`, `buildModel`, and the schema; `computeAll` arrives in another card. **Implement `lib/engine/compute.ts` with `computeProject(project, catalog)` that calls `computeAll` if it exists in the module (`import * as engine`), otherwise builds a partial `Results` with only `model` (other fields empty/zeroed, typed).** That way the app works now and starts showing everything once the full engine is integrated.

## Deliverables
1. **Store** `lib/store/editor.ts`: `useEditor = create<EditorStore>()(...)` following `lib/store/types.ts`. `update` uses `produceWithPatches` (Immer, `enablePatches()`), stores patches/inverses, clears `future`, increments `revision`, revalidates with the engine's `Project.safeParse` (stores `issues`; an invalid project remains editable but is not recomputed). `updateCoalesced` merges entries with the same label within < 600 ms. `applyPatches` (AI). Unlimited history. Useful selectors exported (e.g., `useSelectedObject()`). Vitest tests of the store (update/undo/redo/coalesce/applyPatches/issues).
2. **Worker** `workers/engine.worker.ts` with Comlink implementing `EngineWorkerApi` (from `lib/store/types.ts`), using `getCatalog()` from `@chalecad/catalog` and `lib/engine/compute.ts`. Client `lib/engine/client.ts` (singleton, `new Worker(new URL('../../workers/engine.worker.ts', import.meta.url), { type: 'module' })`). Hook `hooks/useEngine.ts`: observes `revision`, sends the project to the worker (last one wins: discard stale responses), calls `setResults`. Fallback to computing on the main thread if the Worker fails (with a console warning). Show the computation time in the UI.
3. **Local persistence** `lib/storage/indexeddb.ts`: `IndexedDbAdapter implements StorageAdapter` with `idb-keyval` (separate stores for projects and versions). `lib/storage/index.ts` exports `getStorage()` (for now always IndexedDB). Debounced autosave (1.5 s) of the current project; when opening `/editor` without `?id`, reopen the last project; with `?id=<id>` open that one; with none, open the 6.5 x 8.5 chalet template. Indicator "Salvo há X s" (Saved X s ago) / "Salvando…" (Saving…) in the top bar.
4. **Templates** `lib/project/templates.ts`: `createProject(kind, params)` for `gable_mezzanine` (same as the fixture `packages/engine/fixtures/gable-6.5x8.5-mezzanine.json`, adapting the openings to the dimensions) and `a_frame` (with optional mezzanine at the back, door, and glazed front gable end); new IDs with `crypto.randomUUID().slice(0, 8)` prefixed (`w-`, `o-`, `s-`). Editing helpers in `lib/project/edit.ts` (pure, tested): adjust the mezzanine when width/depth changes, keep openings inside the walls when dimensions shrink (clamp), etc.
5. **New-project wizard** `components/editor/NewProjectDialog.tsx`: step 1 typology (illustrated cards with a simple SVG of each shape: gable roof with mezzanine, A-frame; future typologies appear disabled with an "em breve" (coming soon) badge); step 2 main dimensions (width, depth, ceiling height/ridge height, pitch, mezzanine yes/no) with a numeric area preview; step 3 name and UF (state). Opens automatically on first visit.
6. **Editor layout** (refine what exists in `app/editor/page.tsx` and `components/editor/EditorShell.tsx`, keeping the F0-T06 visual direction): top bar with logo, editable name, New, Open (.json file via the worker's `validate`, with a pt-BR error dialog), Export JSON, Undo/Redo (with a tooltip showing the label), compute/save status; tool rail on the left (wired to `setTool`, shortcuts V/W/O/E/M/R shown in the tooltip); **left Properties panel** (below); central viewport using the existing `<Viewport>` (props `model`, `apiRef`, `onSelectHost`; wire selection to the store: if the component keeps selection internally, you MAY add controlled props `selectedId`/`hoverId`/`highlight` in `components/scene/Viewport.tsx`, `ViewportCanvas.tsx`, and `BuildingView.tsx` — the only exception to the rule of not touching the scene, props only, without changing the visuals) with `results.model`, hover and selection wired to the store; right panel: the current `components/editor/ResultsPanel.tsx` (from F0-T06) now reads `results` from the store (area, piece count, computation time); another card (F1-W2) replaces it with `components/results/ResultsPanel.tsx`, so keep its import in a single place in `EditorShell`; validation banner when `issues` is not empty (clickable list).
7. **Properties panel** `components/editor/properties/`: with no selection, collapsible sections: **Typology** (fields of the active typology with Slider + NumberInput with unit; pitch in degrees with the % equivalent; switching typology with confirmation); **Mezzanine** (on/off; depth and front/back position; guardrail); **System** (40/60 spacing, stud/joist/rafter profiles in a Select from the catalog filtering by family/web, OSB/strap bracing, exterior/interior/wet assemblies); **Roof** (roof panel, ridge axis, gutters); **Foundation** (thickness, border, edge beam); **Site** (UF, wind V0, soil). With a selection, the object inspector: opening (type, width, height, sill, position along the wall, delete), interior wall (length, wet area, assembly, delete), stair (type, width, rotation, delete), exterior wall/roof plane (shows data and the list of openings, "adicionar janela"/"adicionar porta" (add window/add door) button that creates one at the middle of the wall). Edits via `updateCoalesced` on sliders and `update` on discrete actions.
8. **Shortcuts**: Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, Delete/Backspace (deletes selection), Esc (clears selection/tool), tool letters. Do not fire inside inputs.
