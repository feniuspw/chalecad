# F3-W2: IA analista (Claude com tool use), patches aprovados, roteiro de obra e pacote do engenheiro

**Objetivo:** painel "Analista" no editor: a IA lê o projeto e os resultados dos motores por ferramentas, responde perguntas, propõe variantes (recalculadas pelo motor real antes de mostrar) e edições como patch JSON que o usuário aprova. Também telas de roteiro de obra e pacote do engenheiro (dados determinísticos do motor: `buildConstructionGuide`, `buildEngineerPackage` em `@chalecad/engine`).

**Pode alterar:** `apps/web/app/api/ai/**`, `apps/web/lib/ai/**` (+ testes), `apps/web/components/ai/**`, `apps/web/components/reports/**`, `apps/web/app/editor/relatorios/**` (se fizer rota própria), `apps/web/.env.example`.
**Não altere:** `lib/store/types.ts`, `packages/**`, `package.json` (o `@anthropic-ai/sdk` já está instalado). Encaixe: pode editar `apps/web/components/results/ResultsPanel.tsx` só para adicionar a aba **Analista** (ícone Sparkles) que renderiza `AnalystPanel`, e `apps/web/components/editor/TopBar.tsx` só para adicionar o botão/menu **Relatórios** (Roteiro de obra, Pacote do engenheiro) que abre os Dialogs.

## Servidor `app/api/ai/route.ts` (runtime nodejs)
- Desligado se `AI_ENABLED !== 'true'` ou sem `ANTHROPIC_API_KEY`: responde 503 com `{ disabled: true, reason }`; a UI mostra estado "IA desligada" com instruções (`AI_ENABLED=true` e `ANTHROPIC_API_KEY` em `apps/web/.env.local`). Modelo por `AI_MODEL` (padrão `claude-opus-5-5`).
- Corpo: `{ project, messages: [{ role, content }] }` (conversa curta em memória no cliente). Valida o projeto com o schema do engine.
- Loop de tool use com `@anthropic-ai/sdk` (`new Anthropic()`, `client.messages.create({ model, max_tokens: 4096, system, tools, messages })`; enquanto `stop_reason === 'tool_use'`, executa cada bloco `tool_use` e devolve `tool_result` com o mesmo `tool_use_id`; limite de 8 iterações). Ferramentas, todas executadas no servidor com `computeAll` + `getCatalog()` (funções puras):
  - `getProject` → JSON do projeto.
  - `getQuantities` → linhas resumidas por etapa (item, quantidade, unidade, peso) + áreas + índice de aço.
  - `getStructuralReport` → verificações (label, taxa, status, detalhe, sugestão).
  - `getBudget` → totais, por etapa, top 10 linhas mais caras.
  - `simulateVariant({ patch: JsonPatchOp[] , label })` → aplica patch (RFC 6902 subset: replace/add/remove; implemente em `lib/ai/patch.ts`, testado) numa cópia, valida, roda o motor e devolve diferenças (custo total, R$/m², peso, aço kg/m², pior taxa estrutural, nº de alertas) contra o projeto atual.
  - `proposePatch({ patch, label, rationale })` → não aplica: valida e registra a proposta para a UI (devolve ok/erros ao modelo).
- System prompt (pt-BR): papel de analista para autoconstrutor; **só citar números vindos de ferramentas, sempre indicando a ferramenta entre colchetes, ex.: "R$ 138.869 [getBudget]"**; nunca afirmar que a estrutura está aprovada; recomendar engenheiro com ART; para edições, usar `proposePatch`; para comparar alternativas, `simulateVariant` antes de opinar; respostas curtas e práticas; explicar caminhos JSON do projeto no contexto do schema (inclua um resumo do schema: campos principais de typology, system, levels, walls, openings, stairs, roof, budget).
- Resposta: `{ text, proposals: [{ id, label, rationale, patch, preview: diffs }], toolCalls: [{ name, input, summary }] }`. Aviso fixo de ART anexado na UI.
- Limite simples por IP em memória (ex.: 30 req/h) e tratamento de erros da API com mensagem pt-BR.

## Cliente
- `components/ai/AnalystPanel.tsx`: chat bonito (mensagens, indicador "analisando…", chips de ferramentas usadas com o resumo), sugestões de perguntas iniciais ("O que mais pesa no orçamento?", "Quanto economizo trocando placa cimentícia por OSB com siding?", "Revise a estrutura", "Aumenta o mezanino em 1 m"). Cada proposta vira um cartão com label, justificativa, diff de custo/peso/taxa e botões **Aplicar** (converte JSON Patch em mudanças via `update(label, draft => applyJsonPatch(draft, patch))` do store, com undo) e **Descartar**. Números da resposta com o marcador de ferramenta estilizado (badge discreta).
- Botão "Revisar projeto" que manda a pergunta padrão de revisão.
- `components/reports/ConstructionGuideView.tsx` e `EngineerPackageView.tsx`: renderizam os relatórios do motor com boa tipografia (passos numerados, ferramentas, lista "compre primeiro"; pacote com premissas, tabela de verificações coloridas, perguntas abertas), com botão de imprimir (CSS de impressão) e exportar Markdown. Abrir a partir de um menu "Relatórios" (descreva o encaixe) ou de um Dialog grande.
