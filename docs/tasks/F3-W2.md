# F3-W2: AI analyst (Claude with tool use), approved patches, construction guide, and engineer package

**Goal:** an "Analista" (Analyst) panel in the editor: the AI reads the project and the engine results through tools, answers questions, proposes variants (recomputed by the real engine before being shown) and edits as a JSON patch that the user approves. Also screens for the construction guide and the engineer package (deterministic engine data: `buildConstructionGuide`, `buildEngineerPackage` in `@chalecad/engine`).

**May change:** `apps/web/app/api/ai/**`, `apps/web/lib/ai/**` (+ tests), `apps/web/components/ai/**`, `apps/web/components/reports/**`, `apps/web/app/editor/relatorios/**` (if you build a dedicated route), `apps/web/.env.example`.
**Do not change:** `lib/store/types.ts`, `packages/**`, `package.json` (`@anthropic-ai/sdk` is already installed). Integration: you may edit `apps/web/components/results/ResultsPanel.tsx` only to add the **Analista** tab (Sparkles icon) that renders `AnalystPanel`, and `apps/web/components/editor/TopBar.tsx` only to add the **Relatórios** (Reports) button/menu (Roteiro de obra, Pacote do engenheiro — construction guide, engineer package) that opens the Dialogs.

## Server `app/api/ai/route.ts` (nodejs runtime)
- Disabled if `AI_ENABLED !== 'true'` or `ANTHROPIC_API_KEY` is missing: responds 503 with `{ disabled: true, reason }`; the UI shows an "IA desligada" (AI disabled) state with instructions (`AI_ENABLED=true` and `ANTHROPIC_API_KEY` in `apps/web/.env.local`). Model via `AI_MODEL` (default `claude-opus-5-5`).
- Body: `{ project, messages: [{ role, content }] }` (short conversation kept in memory on the client). Validates the project with the engine schema.
- Tool use loop with `@anthropic-ai/sdk` (`new Anthropic()`, `client.messages.create({ model, max_tokens: 4096, system, tools, messages })`; while `stop_reason === 'tool_use'`, execute each `tool_use` block and return a `tool_result` with the same `tool_use_id`; limit of 8 iterations). Tools, all executed on the server with `computeAll` + `getCatalog()` (pure functions):
  - `getProject` → project JSON.
  - `getQuantities` → summarized lines per stage (item, quantity, unit, weight) + areas + steel index.
  - `getStructuralReport` → checks (label, ratio, status, detail, suggestion).
  - `getBudget` → totals, per stage, top 10 most expensive lines.
  - `simulateVariant({ patch: JsonPatchOp[] , label })` → applies the patch (RFC 6902 subset: replace/add/remove; implement in `lib/ai/patch.ts`, tested) to a copy, validates, runs the engine, and returns differences (total cost, R$/m², weight, steel kg/m², worst structural ratio, number of warnings) against the current project.
  - `proposePatch({ patch, label, rationale })` → does not apply: validates and records the proposal for the UI (returns ok/errors to the model).
- System prompt (pt-BR): role of analyst for a self-builder; **only cite numbers that come from tools, always indicating the tool in square brackets, e.g., "R$ 138.869 [getBudget]"**; never state that the structure is approved; recommend an engineer with ART; for edits, use `proposePatch`; to compare alternatives, use `simulateVariant` before giving an opinion; short, practical answers; explain project JSON paths in the context of the schema (include a schema summary: main fields of typology, system, levels, walls, openings, stairs, roof, budget).
- Response: `{ text, proposals: [{ id, label, rationale, patch, preview: diffs }], toolCalls: [{ name, input, summary }] }`. Fixed ART notice appended in the UI.
- Simple in-memory per-IP limit (e.g., 30 req/h) and handling of API errors with a pt-BR message.

## Client
- `components/ai/AnalystPanel.tsx`: polished chat (messages, "analisando…" (analyzing…) indicator, chips for tools used with the summary), starter question suggestions ("O que mais pesa no orçamento?", "Quanto economizo trocando placa cimentícia por OSB com siding?", "Revise a estrutura", "Aumenta o mezanino em 1 m"). Numbers in the response with the tool marker styled (discreet badge).
- A "Revisar projeto" (Review project) button that sends the default review question.
- `components/reports/ConstructionGuideView.tsx` and `EngineerPackageView.tsx`: render the engine reports with good typography (numbered steps, tools, "buy first" list; package with assumptions, color-coded table of checks, open questions), with a print button (print CSS) and Markdown export. Open from a "Relatórios" menu (describe the integration) or from a large Dialog.
